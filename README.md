# ZeNOxWeb.ir — مارکت‌پلیس قالب و طراحی سایت

پلتفرم فروش قالب‌های آماده وب با سفارش‌گیری، احراز هویت دو مرحله‌ای (موبایل + ایمیل)،
پیش‌فاکتور تاییدی، پرداخت آنلاین و پنل مدیریت کاملاً ماژولار.
تمام محتوای سایت (هیرو، بخش‌های صفحه اصلی، نمونه‌کارها، دسته‌بندی‌ها، پلن‌ها، وبلاگ،
اطلاعات پشتیبانی و نماد اعتماد) از دیتابیس خوانده می‌شود و از پنل ادمین قابل ویرایش است.

## پشته فناوری

- **Next.js 16 (App Router) + TypeScript**
- **PostgreSQL + Drizzle ORM** (`src/db/schema.ts`)
- احراز هویت سفارشی مبتنی بر **JWT امضاشده HMAC** در کوکی httpOnly + نقش‌های `OWNER` / `ADMIN` / `CUSTOMER`
- **OTP پیامکی (کاوه‌نگار)** و **کد تایید ایمیل (Resend)** — ماژولار و قابل تعویض (`src/lib/otp.ts`)
- **درگاه پرداخت ماژولار** (زرین‌پال + درگاه آزمایشی داخلی) در `src/lib/payments.ts`
- **Tailwind CSS v4** با تم روشن و گلس‌مورفیسم
- **Docker + Docker Compose + Nginx**

## اجرای سریع (Docker)

```bash
cp .env.example .env   # مقادیر را ویرایش کنید
docker compose up -d --build
```

## اجرای محلی

```bash
npm install
cp .env.example .env
npx drizzle-kit push   # ساخت جداول
npm run dev
```

داده‌های اولیه (دسته‌بندی‌ها، پلن‌ها، قالب‌های نمونه و مقالات) در اولین درخواست
به‌صورت خودکار seed می‌شوند و **ساختار دیتابیس هم به‌صورت خودکار مهاجرت می‌شود**
(`src/lib/migrate.ts` + `src/lib/seed.ts`). یعنی روی هر سرور جدید یا دیتابیس قدیمی،
جداول و ستون‌ها به‌طور خودکار ساخته/به‌روزرسانی می‌شوند و نیازی به اجرای دستی
`drizzle-kit push` نیست.

### حساب مالک (Production)

هیچ حساب تستی در پروداکشن ساخته نمی‌شود. فقط **یک حساب مالک** بر اساس متغیرهای
محیطی زیر ساخته می‌شود:

```env
OWNER_NAME=مدیر سایت
OWNER_EMAIL=admin@yourdomain.ir
OWNER_PHONE=09120000000
OWNER_PASSWORD=your-strong-password
```

اگر این متغیرها تنظیم نشوند و دیتابیس خالی باشد، یک حساب مالک پیش‌فرض
(`admin@zenoxweb.ir` / `Owner@12345`) ساخته می‌شود که **باید بلافاصله پس از اولین
ورود، رمز آن را تغییر داده و ایمیل را در `.env` تنظیم کنید**.

سایر کاربران (ادمین‌های دیگر و مشتریان) از طریق پنل مدیریت یا ثبت‌نام عادی ساخته
می‌شوند.

## فرآیند سفارش

`AWAITING_QUOTE` → `QUOTED` → `APPROVED_BY_CUSTOMER` → `PAID` → `IN_PROGRESS` → `DEPLOYED` → `DELIVERED`

1. مشتری قالب را انتخاب و به سبد اضافه می‌کند، پلن سرور و توضیحات سفارشی‌سازی را وارد می‌کند.
2. ثبت درخواست فقط پس از تایید موبایل و ایمیل ممکن است.
3. ادمین در پنل، **هزینه طراحی متغیر** و یادداشت را وارد می‌کند؛ سیستم
   `هزینه طراحی + هزینه سرور` را به‌عنوان پیش‌فاکتور به مشتری نشان می‌دهد.
4. مشتری پیش‌فاکتور را تایید می‌کند و سپس کل مبلغ را یکجا پرداخت می‌کند.
5. ادمین وضعیت اجرا، دامنه و اطلاعات سرور را ثبت می‌کند تا تحویل نهایی.

## ساختار پروژه

```
src/
├── app/
│   ├── (site)/            صفحات عمومی: لندینگ، فروشگاه، قالب، وبلاگ، سبد، حساب، پرداخت
│   ├── admin/             پنل مدیریت ماژولار (داشبورد، سفارش، قالب، دسته، پلن، وبلاگ، صفحه‌ساز، تنظیمات، کاربران، مالی)
│   ├── actions/           سرور اکشن‌ها (auth / orders / admin)
│   └── api/               health، ثبت بازدید، callback درگاه
├── components/            Navbar، Footer، سبد خرید، کارت قالب
├── db/                    اسکیمای Drizzle و کلاینت دیتابیس
└── lib/                   auth، otp، payments، settings، queries، seed، format
```

## ماژول‌های پنل ادمین

- **داشبورد**: بازدید، تعداد درخواست، نرخ تبدیل، نرخ تایید پیش‌فاکتور، درآمد کل و بر اساس پلن، روند ۳۰ روزه، پرفروش‌ترین قالب‌ها
- **سفارش‌ها**: فیلتر بر اساس وضعیت، صدور پیش‌فاکتور، ثبت دامنه/سرور، تغییر وضعیت
- **پشتیبانی**: مدیریت تیکت‌های مشتری، فیلتر بر اساس وضعیت و اولویت، پاسخ‌دهی به مشتری، ارسال خودکار ایمیل
- **نمونه‌کارها**: CRUD کامل + انتخاب چند دسته‌بندی + فعال/غیرفعال + featured
- **دسته‌بندی‌ها**: CRUD و ترتیب ستون‌های صفحه فروشگاه
- **پلن‌های سرور**: قیمت ماهانه، ظرفیت و مصرف
- **وبلاگ**: محتوا + سئو (عنوان سئو، متا، کلمات کلیدی) + وضعیت انتشار
- **صفحه‌ساز صفحه اصلی**: افزودن/حذف/ترتیب/نمایش بخش‌ها و آیتم‌ها
- **تنظیمات سایت**: هیرو، تلگرام، واتساپ، نماد اعتماد، تماس، شبکه‌های اجتماعی و **الگوی ایمیل تیکت پشتیبانی**
- **کاربران (فقط مالک)**، **مالی و درگاه (فقط مالک)**

## سیستم تیکت‌های پشتیبانی

**مشتریان:**
- ایجاد تیکت جدید با موضوع، پیام و انتخاب اولویت (کم/عادی/بالا/فوری)
- مشاهده‌ی تمام تیکت‌های خود در داشبورد شخصی
- پاسخ‌دهی به تیکت‌های باز
- دریافت خودکار ایمیل تأیید ثبت تیکت
- دریافت خودکار ایمیل در زمان پاسخ تیم پشتیبانی

**تیم پشتیبانی:**
- مدیریت تیکت‌ها از پنل ادمین
- فیلتر بر اساس وضعیت (باز/پاسخ داده شده/بسته شده) و اولویت
- پاسخ فوری به مشتریان
- تغییر وضعیت تیکت
- ارسال خودکار ایمیل به مشتری هنگام پاسخ‌دهی

**الگوی ایمیل قابل‌تخصیص:**
- مالک می‌تواند الگوی ایمیل تیکت‌های پشتیبانی را در "تنظیمات سایت" تنظیم کند
- متغیرهای قابل استفاده: `{customer_name}`, `{ticket_id}`, `{subject}`, `{message}`, `{support_phone}`, `{support_email}`
- ایمیل‌ها از طریق Resend ارسال می‌شوند (در صورت تنظیم کلید API)
